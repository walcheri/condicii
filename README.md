# Потенциальные кондиции

React + Vite во `frontend/`, Express API и SQLite в `backend/`. Node.js 24 или новее.

## Локальный запуск

```sh
npm install
npm run dev
```

Открыть http://localhost:5173. Vite направляет `/api` на Express (порт 10000). В PowerShell с запретом запуска сценариев используй `npm.cmd` вместо `npm`.

## Сборка и запуск

```sh
npm ci
npm run build
npm start
```

Сайт и API доступны на http://localhost:10000. `PORT` меняет порт сервера; при разработке также измени порт прокси в `vite.config.js`. `DATA_DIR` задаёт каталог базы (по умолчанию `data/`). `NODE_ENV=production` включает Secure cookie и требует HTTPS.

## Аккаунт и сообщество

Вход или регистрация обязательны. Логин: 3–24 буквы, цифры, дефисы или подчёркивания; пароль: 8–128 символов. Пароли хранятся в виде scrypt-хешей с индивидуальной солью. Сессия действует 30 дней через HttpOnly cookie; выход отзывает её на сервере. После входа открывается сообщество. Новости публикуются под логином автора.

Регистрация выдаёт 2 500 Минеток, арбуз, тыкву и пельмени. Баланс, инвентарь и история сохраняются в аккаунте и доступны после входа с другого устройства. Старые гостевые сессии не дают доступ; для использования сайта нужно зарегистрироваться. При открытии существующей базы оружие в инвентарях и истории заменяется новыми предметами с прежней стоимостью.

## Апгрейд

Обычные предметы: арбуз, тыква, пельмени, Яндекс бутылка воды. Редкие: диск GTA VI, свидание с Залмой. Эпический: лисичка потенциала. Легендарный: Солярис. Это игровые предметы с внутренними ценами; платежи и выдача реальных предметов не подключены.

Ставка: один предмет или целое число Минеток. Цель должна стоить дороже. Шанс равен отношению стоимости ставки к стоимости цели, округлённому вниз до 0,0001%. Сервер использует криптографический генератор `randomInt` и миллион равновероятных позиций. При победе выдаётся цель; ставка расходуется при любом исходе. Предметы можно обменивать обратно на Минетки.

Списание, выдача и история выполняются одной SQLite-транзакцией. `requestId` защищает повтор запроса от повторного списания. Незавершённая операция хранится в sessionStorage: после сетевой ошибки или обновления вкладки нажми «Проверить операцию».

Новости и состав группы сохранены. При первом запуске существующий `DATA_DIR/news.json` переносится в SQLite без удаления исходного файла.

## API

- `GET /api/health` — проверка сервера и базы.
- `POST /api/auth/register`, `POST /api/auth/login` — `{ username: "Игрок", password: "..." }`.
- `POST /api/auth/logout` — `{}`; отзыв текущей сессии.
- `GET /api/me` — баланс, инвентарь, последние 20 операций.
- `GET /api/catalog` — каталог с серверными ценами.
- `POST /api/upgrade/quote` — `{ mode: "balance", amount: 250, targetId: "gta6" }` или `{ mode: "skin", inventoryId: "...", targetId: "gta6" }`.
- `POST /api/upgrade` — тот же объект и уникальный `requestId`; повторять с тем же телом при неизвестном результате.
- `POST /api/inventory/sell` — `{ inventoryId: "..." }`.
- `GET /api/news`, `POST /api/news` — новости сообщества.

Все API, кроме проверки здоровья, регистрации и входа, требуют сессию аккаунта. SQLite должна храниться на постоянном диске, чтобы аккаунты переживали пересоздание контейнера.

## Проверки

`npm test` проверяет шансы, границу сектора, оба исхода, владение предметами, повтор запроса, откат транзакции, сохранение базы и HTTP API. `npm run build` собирает фронтенд. `npm run test:browser` проверяет интерфейс в установленном Google Chrome, включая мобильную ширину и восстановление операции после потери ответа; для другой среды измени `channel` в `playwright.config.js`.

## Render

Для сервиса, созданного вручную, задай в Render → Settings:

- Тип сервиса: Web Service, среда Node.
- Root Directory: пустое поле (корень репозитория с `package.json`).
- Build Command: `npm ci --include=dev && npm run build`.
- Start Command: `npm start`.
- Health Check Path: `/api/health`.
- Переменные окружения: `NODE_VERSION=24.13.0`, `NODE_ENV=production`.

Сохрани настройки и запусти новый деплой. Эти же команды указаны в `render.yaml` для Blueprint. Для вручную созданного сервиса настрой команды в Dashboard.

Ошибка `ENOENT ... dist/index.html` означает, что сервер запущен без собранного фронтенда. В логе сборки должен быть успешный `vite build` с файлом `dist/index.html`. Флаг `--include=dev` устанавливает Vite и React-плагин даже при `NODE_ENV=production`. Проект использует npm и `package-lock.json`; предупреждения Yarn `No lockfile found` и `package-lock.json found` означают, что установка запущена через Yarn. Замени её на указанную Build Command, сохранив `package-lock.json`. Каталог `dist/` создаётся при деплое и не хранится в Git.

`render.yaml` запускает сборку фронтенда и Express на Node.js 24. Для сохранения SQLite между деплоями подключи Persistent Disk с точкой монтирования `/var/data` и установи `DATA_DIR=/var/data`. Без постоянного диска данные сбрасываются при пересоздании контейнера. База рассчитана на один экземпляр приложения с локальным диском.
